Implement and Manage Virtual Networking

Branch VNet with bidirectional peering, NSGs, static IPs, user-defined routes, a storage service endpoint, private DNS and a Standard Load Balancer.

Project overview

An additional subnet and a separate branch virtual network were created, followed by bidirectional VNet peering, network security groups, static private and public IP addresses, a route table with user-defined routes, a Microsoft.Storage service endpoint and a private DNS zone with a virtual network link. A Standard Load Balancer was deployed and Azure Network Watcher was enabled in East Asia. Configuration was verified in the Azure Portal, Azure CLI and PowerShell.

Objectives

  • Extend an existing network with an additional subnet and a branch VNet.
  • Control traffic with NSG rules and user-defined routes.
  • Provide private name resolution, service endpoints and load balancing.

Implementation

  • Created an additional subnet and the branch virtual network.
  • Configured bidirectional peering between the main and branch VNets.
  • Configured nsg-branch-1 with an RDP deny rule and an HTTPS allow rule.
  • Assigned the static private IP 10.20.1.10 and a Standard public IP.
  • Created route table rt-branch-1 with a route blocking 192.0.2.0/24 and associated it with snet-branch-1.
  • Enabled the Microsoft.Storage service endpoint on the branch subnet.
  • Created private DNS zone lab.inno.internal with a virtual network link.
  • Deployed Standard Load Balancer lb-branch-1 with a TCP health probe and an HTTP port 80 rule.
