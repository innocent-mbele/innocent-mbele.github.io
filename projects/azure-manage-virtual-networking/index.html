Implement and Manage Virtual Networking

I extended my Azure network with a branch VNet and peering. I added NSGs, static IPs, a custom route table, a storage service endpoint, private DNS and a Standard Load Balancer.

Overview

In this project I extended an existing Azure network. I added a subnet and created a separate branch virtual network, then connected the two with peering in both directions. I configured security rules, static private and public IP addresses, a route table with my own routes, a service endpoint for Azure Storage and a private DNS zone linked to the network. I also deployed a Standard Load Balancer and enabled Network Watcher in East Asia. I checked the setup in the portal, Azure CLI and PowerShell.

What I set out to do

  • Extend an existing network with a new subnet and a branch network.
  • Control traffic with NSG rules and custom routes.
  • Add private name resolution, a storage service endpoint and load balancing.

What I did

  • I created the extra subnet and the branch virtual network.
  • I set up peering between the main and branch networks in both directions.
  • I configured nsg-branch-1 with a rule that blocks RDP and a rule that allows HTTPS.
  • I set the static private IP 10.20.1.10 and added a Standard public IP.
  • I created the route table rt-branch-1 with a route that blocks 192.0.2.0/24 and attached it to snet-branch-1.
  • I enabled the Microsoft.Storage service endpoint on the branch subnet.
  • I created the private DNS zone lab.inno.internal and linked it to the network.
  • I deployed the Standard Load Balancer lb-branch-1 with a TCP health probe and an HTTP rule on port 80.
